What changes when an agent changes models

I checked Cursor, OpenCode, Lovable, Make, and Zapier. The question was whether each product swaps only the model or also changes the instructions, tools, and context around it.

The answer

Cursor, OpenCode, and Lovable say they adjust the agent for each model. Make and Zapier expose model choice, agent roles, and capability limits, but they do not publish the same level of model-specific prompt detail.

The split

Three products tune the agent. Two expose controls without showing the full setup.

Cursor, OpenCode, and Lovable publish direct evidence that the selected model can change its prompt, tools, tool descriptions, edit format, or context handling.

Make and Zapier let users choose models and tools. They also route work through agent roles or model tiers. Their public material does not show a separate prompt and tool contract maintained for every model.

The products

What the evidence says

Direct means source code or a first-party technical post describes the model-specific change. Documented means the feature is public but the internal setup is not.

Cursor

Coding agent
Direct

Cursor gives each model its own instructions and tools, then tests the result with Cursor Bench.

What changes

For Codex, Cursor changed tool names, lint instructions, progress updates, action rules, message order, and handling of reasoning state.

What stays unclear

Cursor documents skills separately from model instructions. It has not said that each model gets different skill files.

OpenCode

Coding agent
Direct

OpenCode maps model IDs to separate prompts and passes the model and provider IDs into its tool registry.

What changes

The code has prompt files for Codex, GPT, Claude, Gemini, Kimi, Trinity, Meta, and a fallback. The tool registry can also change which tools a model receives.

What stays shared

Changing the model does not replace the skills. OpenCode filters skills through the selected agent's permissions.

Lovable

App builder
Direct

Lovable says it changes the instructions, tools, context, and summaries for each model.

What changes

During a build, Lovable can switch the model, rewrite tool descriptions, change how much project context it sees, or summarize earlier work.

How it tests

Lovable judges the finished app, not a single response. Its exact internal mappings remain private.

Make

Workflow agent and builder
Documented

Make lets users choose the model, tools, knowledge, and models assigned to subagents.

What changes

An agent can use Make modules, scenarios, MCP tools, or other agents. Subagents can use different models for focused jobs.

What stays unclear

Make has not published separate prompts or tool definitions for each model. Maia's model routing and prompt setup are also private.

The selected tier decides whether the model can use tools and knowledge. Users choose which action fields stay fixed and which ones the agent fills in.

Zapier has not published separate prompts or tool definitions for each model. Copilot's routing and tests are also private.

What to take from this

The useful pattern is small, tested changes.

Tune the part that fails

Change the edit format when edits fail. Change tool instructions when calls fail. Change context handling when the model forgets earlier work.

Keep skills reusable

None of these products provides good evidence that skill files should change with every model. Keep the procedure stable and declare the capabilities it needs.

Mark private details as unknown

Make and Zapier may tune prompts internally. Their public docs do not prove it, so the report does not claim it.
