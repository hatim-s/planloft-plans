TL;DR

Do not ship this snapshot to a critical on-prem environment yet. The audit found five immediate release blockers: plaintext registry credentials, stored-expression code execution in Matrix SSR, native session-cookie disclosure, anonymous access to unpublished interface records, and tenant-unsafe Tensor fallbacks.

The fixes are concrete. Remove tenant-authored JavaScript from shared server processes, make every route and tenant lookup fail closed, isolate authored browser code, and make the build chain reproducible. Then prove the result with a backend authorization matrix and an environment-level penetration test.

Audited commit: 76785cee0cf020c207c29151ddc0df1e1d3de4c8

Decision: release blocked until every P0 item is fixed and independently verified.

What this audit covered

The review split into parallel passes for RBAC and tenant isolation, low-code execution, middleware and proxy trust, and software supply chain. It inspected the source snapshot, existing security tests, GitHub Actions, package policy, container builds, and the production dependency graph.

The audit did not test live customer data, validate whether exposed registry tokens remain active, or attack a deployed environment. The enforcing backend for many generated API clients is not part of www, so object-level authorization still needs black-box verification.

No source files were changed during the audit.

P0 release blockers

Plaintext package-registry credentials

The tracked root .npmrc contains credential-shaped plaintext tokens for npm and Tiptap's registry at lines 3 and 5. Their values are intentionally omitted from this report.

Impact. Anyone with repository or artifact access may obtain package-registry authority. A compromised read token can disclose private packages. A write token can publish malicious packages under a trusted scope.

Required fix. Revoke and rotate both credentials. Inspect registry access logs and token scopes. Remove the values from the current tree and coordinated Git history, then purge CI caches, artifacts, and images that may contain them. Keep only environment-variable placeholders in .npmrc. Use read-only credentials for installation and OIDC or trusted publishing for releases.

Acceptance test. Full-history secret scanning returns no live credential. A clean build succeeds with credentials injected only at the step that needs them.

Stored expressions execute in the shared SSR process

packages/carbon/src/no-code/utils/indirectEval.ts:83-303 compiles stored expression text with new Function. Matrix evaluates stored attributes and conditional themes during SSR through apps/matrix/src/app/layout.tsx:221-269.

The repository's Node-environment security suite documents that default evaluation can reach and modify process.env:

packages/carbon/src/no-code/utils/__tests__/recursiveUpdate.security.test.ts:14-108

The current mitigation in getShouldEvaluateResult.ts:23-32 depends on an optional interface flag. It stops specific nested re-evaluation paths. It does not turn new Function into a sandbox.

Impact. A malicious app author, compromised builder account, unsafe import, or injectable nested value can run code in the Matrix server process. That process may hold environment secrets, filesystem access, internal-network reachability, and other tenants' work.

Required fix. Disable authored expression evaluation during SSR globally. Replace JavaScript formulas with an allowlisted AST interpreter that supports own-property reads and explicit pure operations. If arbitrary code remains a product requirement, run it in a disposable process, container, or microVM with no inherited credentials, writable mounts, or tenant-shared lifetime. Enforce CPU, memory, and wall-clock limits. Node's vm module and shadowed globals are not security boundaries.

Acceptance test. Server bundles contain no authored-code path to eval, Function, new Function, dynamic import, process globals, filesystem, network, or constructor-chain escape. Infinite loops terminate outside the renderer process.

Native WebView forwards the session cookie to arbitrary URLs

Builder-controlled navigation reaches apps/matrix-native/src/modules/webview/pages/WebViewPage/WebViewPage.tsx:103-170. The component attaches the raw stored session cookie to the initial URL and to arbitrary popup targets.

Impact. An app action can direct a signed-in user to an attacker-controlled URL and disclose the application session.

Required fix. Attach credentials only after an exact normalized comparison of scheme, host, and port with the configured tenant origin. Apply the same rule to redirects and popups. Open external destinations in the OS browser or a fresh cookieless WebView. Disable WebView debugging in release builds.

Acceptance test. Initial navigation, redirects, and popups to every non-tenant origin receive no cookie or authorization header.

Anonymous preview exposes unpublished interface records

apps/platform/src/app/(application)/_internal/preview/[interfaceId]/page.tsx:14-58 accepts a caller-selected interface ID and passes the complete record to a client component. fetchAuthInterface.ts:22-45 sends no user credential, while the Platform proxy excludes _internal routes.

The record may contain custom code, functions, permission structure, security configuration, and secret-bearing integration settings.

Required fix. Validate the session, tenant, and exact-interface VIEW or EDIT permission inside the route. Authenticate screenshot workers with a short-lived capability bound to tenant, interface, action, audience, and expiry. Return a purpose-built preview DTO instead of InterfaceEntity.

Acceptance test. Anonymous, wrong-tenant, and wrong-interface requests return indistinguishable 401 or 404 responses and never serialize the entity.

Tensor's legacy fallback can cross tenant ownership

apps/tensor/src/appDir.ts:47-94 treats missing, malformed, or unreadable ownership metadata as unowned, then permits a root-level legacy-directory fallback. The code also records that app IDs are not globally unique.

Impact. If such a legacy directory exists, one customer can receive another customer's deployed application files.

Required fix. Inventory and migrate every legacy directory before rollout. Remove the unscoped fallback. Fail readiness when ownership is missing, malformed, duplicated, or ambiguous. Resolve application ownership from an authoritative immutable mapping.

Acceptance test. Startup or readiness fails while any legacy app lacks a valid customer mapping. Cross-tenant app-ID collisions always return an error.

P1 findings by category

RBAC and authentication

Tensor treats the presence of _at or _aut as a session and allows private application rendering on auth-service failures in apps/tensor/src/authGate.ts:24-70. Matrix has a similar cookie-name check and continues after rejected user-context calls in apps/matrix/src/proxy-utils/handlePrivatePages.ts:129-273.

Require a successful, schema-valid user-context response with an expected subject and tenant. Deny every other response. Return 503 without rendering when the auth dependency fails.

The test-studio UI can also request run-as sessions for a selected user. The backend implementation sits outside this repository. Before release, prove that the backend checks caller privilege, tenant equality, role ceilings, application binding, short expiry, single use, revocation, and immutable audit logging.

Browser execution and stored XSS

Custom code should carry a separate permission from ordinary content editing. Publishing it should require review, a signed immutable version, and an audit entry. Critical installations need a global switch that disables all authored JavaScript.

Middleware and proxy trust

packages/network/src/utils/proxyHeaders.ts:10-14 explicitly documents that deleting reserved headers from the middleware request object does not remove them from the downstream request. Forged x-ua-* values can influence public or private routing, application selection, pathname, and tenant prefixes.

Clone incoming headers, remove the complete reserved namespace, author trusted values, and pass the sanitized bag through NextResponse.next({ request: { headers } }). Configure ingress to reject or overwrite every external x-ua-* and forwarded-host header.

Tensor also builds its platform origin from x-forwarded-host and x-forwarded-proto, then forwards the request cookie to that origin in apps/tensor/src/handler.ts:90-100 and apps/tensor/src/resolver.ts:62-73. Use a fixed internal platform origin and validate public hosts against authoritative mappings.

Privileged CI shell injection

The manually supplied image tag in .github/workflows/deploy-docker-image.yml:25-27 reaches a shell-expanded Helm command after AWS credentials and kubeconfig are installed in .github/actions/helm-deploy/action.yaml:55-105.

Validate tags with a strict OCI-tag pattern. Pass workflow inputs through environment variables and quote every expansion. Prefer argument arrays over generated shell. Require production environment approval and narrow the assumed role to the exact cluster and namespace.

Supply chain and build integrity

The intended package quarantine is inactive. minimumReleaseAge appears at the top level of package.json:211, while pnpm config reports it as undefined. CI runs plain pnpm install without a lifecycle-script allowlist in .github/actions/setup-env/action.yaml:20-33.

Set a release-age quarantine in pnpm-workspace.yaml, use frozen lockfiles, and explicitly allow the few dependency build scripts the repository needs. Fetch dependencies in a job with no cloud credentials.

Privileged workflows execute mutable third-party code. Examples include major-version action tags, Sonar's @master, an unversioned global codeowners-generator that later pushes to the repository, and a latest Wiz binary downloaded without checksum verification. Pin actions and tools to full commits or digests. Verify signatures or checksums before execution.

Container builds are not reproducible. Production images use mutable node:lts-alpine; several Dockerfiles also run apk upgrade against the latest repository state. Pin base images by digest, rebuild through an internal mirror, sign the result, generate an SBOM and provenance attestation, and deploy by digest rather than tag.

The audited lockfile reports 6 high, 8 moderate, and 5 low advisories across 3,364 production dependencies. The high set includes four fast-uri host-confusion or SSRF advisories through Platform's AJV path and two image-size infinite-loop advisories through Matrix Native. Upgrade fast-uri to at least 3.1.6; resolve or isolate the affected image-size path.

P2 engineering controls

The repository carries 59 dependency patches, several without version-qualified keys, while allowUnusedPatches is enabled. Disable unused patches, bind every patch to a package version and hash, record its upstream reference, and require security ownership for changes under patches/**.

SheetJS is fetched from an external CDN tarball without lockfile integrity metadata. Mirror it into an immutable internal registry and pin its digest.

For a real air gap, ship one signed bundle containing images, charts, package artifacts, SBOMs, vulnerability exceptions, and verification keys. Installation and runtime should make no public DNS or HTTP requests. Enforce this with default-deny egress rather than documentation.

Safe browser reproductions

The browser examples below reproduce three unsafe mechanisms with fake state on localhost. They do not read repository secrets, contact a tenant, or send data outside the machine.

Chrome verified these outputs:

  1. Dynamic evaluation changed a host-owned object to secretVisible: true.
  2. Authored srcDoc called a function in its parent document.
  3. A caller-supplied x-ua-public-interface header changed the server-selected route from private to external.

Reproduction 1: dynamic source crosses into host state

<button id="run">Run proof</button>
<output id="result"></output>
<script>
  document.querySelector('#run').addEventListener('click', () => {
    const hostState = { secretVisible: false, audit: [] };
    const storedExpression =
      'hostState.secretVisible = true; hostState.audit.push("expression crossed host boundary")';

    new Function('hostState', storedExpression)(hostState);
    document.querySelector('#result').textContent = JSON.stringify(hostState);
  });
</script>

Expected output:

{"secretVisible":true,"audit":["expression crossed host boundary"]}

A hardened SSR evaluator must reject the expression before compilation.

Reproduction 2: same-origin srcDoc changes its parent

<output id="result">Not run</output>
<div id="slot"></div>
<script>
  window.recordFrameEscape = (message) => {
    document.querySelector('#result').textContent = message;
  };

  const frame = document.createElement('iframe');
  frame.setAttribute('sandbox', 'allow-scripts allow-same-origin');
  frame.srcdoc = '<script src="/frame-payload.js"></scr' + 'ipt>';
  document.querySelector('#slot').replaceChildren(frame);
</script>

/frame-payload.js contains:

parent.recordFrameEscape('Authored srcDoc changed its parent');

Expected output: Authored srcDoc changed its parent.

Remove allow-same-origin for authored srcDoc. A hardened frame should fail to access parent.recordFrameEscape.

Reproduction 3: forged proxy context changes routing

Browser call:

const response = await fetch('/proxy-check', {
  headers: { 'x-ua-public-interface': 'true' },
});
console.log(await response.json());

Intentionally unsafe local handler:

const callerSelectedPublicState =
  request.headers.get('x-ua-public-interface') === 'true';

return Response.json({
  acceptedClientHeader: callerSelectedPublicState,
  selectedRoute: callerSelectedPublicState
    ? '/api-endpoint/external'
    : '/api/private',
});

Observed output:

{"acceptedClientHeader":true,"selectedRoute":"/api-endpoint/external"}

A hardened ingress or middleware should strip the header and always select /api/private for this request.

Execution plan

Same day containment

  1. Revoke and rotate the two registry credentials.
  2. Disable every SSR path that evaluates authored JavaScript.
  3. Stop native WebViews from forwarding credentials to non-tenant origins.
  4. Require authentication and exact-interface authorization on the preview route.
  5. Make Tensor and Matrix deny rendering when session validation fails.

Before the next critical release candidate

  1. Remove Tensor's legacy unowned-directory fallback and complete the ownership migration.
  2. Replace dynamic SSR formulas with an AST interpreter.
  3. Isolate iframe content, custom components, and custom code.
  4. Repair proxy-header propagation and ingress header policy.
  5. Remove privileged workflow interpolation.
  6. Pin actions, tools, packages, and base images. Produce signed SBOM and provenance artifacts.
  7. Resolve the current high dependency advisories.

Verification gate

Run an authorization matrix across anonymous, viewer, editor, administrator, and impersonated sessions in two tenants. Exercise read, list, search, export, share, update, delete, publish, execute, and run-as operations with both valid and guessed cross-tenant IDs.

Then test the assembled on-prem installation, not only the source tree:

  • verify ingress strips reserved and forwarded headers;
  • verify default-deny network egress;
  • verify workloads run as non-root with read-only filesystems and restricted service accounts;
  • verify container signatures and admission policy;
  • verify no runtime component contacts a public registry, CDN, telemetry endpoint, or update service;
  • verify logs, error responses, and scanner artifacts contain no secrets;
  • verify backup, restore, key rotation, audit retention, and incident revocation.

Passing unit tests is not the release decision. The release decision depends on proving the assembled system fails closed at every trust boundary.

Definition of ready

The critical on-prem build is ready for an independent penetration test when:

  • every P0 has a merged fix and a negative security test;
  • every P1 has a fix or a documented, time-bounded risk acceptance signed by the security owner;
  • backend RBAC tests show no cross-tenant or role-ceiling bypass;
  • the build is reproducible from mirrored, digest-pinned inputs;
  • every shipped artifact has a signature, SBOM, provenance record, and vulnerability decision;
  • the installation completes and runs with public network access disabled;
  • a fresh reviewer can reproduce the three hardened browser examples and see all three attempts refused.

That is the minimum credible bar for calling this platform ready for a critical environment.
