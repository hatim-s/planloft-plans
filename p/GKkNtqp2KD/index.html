Five parallel audits looked at packages/workflow-code in the executable-workflow-package worktree. The core builder is sound and worth keeping. The packaging, type strictness, and safety around it are not. This report lists what to fix first.

The situation is simple. The package gives you a typed TypeScript builder that emits native UnifyApps workflow JSON. Arrays set order, both condition arms get built while the platform picks at runtime, and .output fields become typed {{ }} references. That model works. Graph guards for trigger first, single use, reachability, and path scoped references all hold. The shared filter contract with NOT_EXISTS to MISSING normalization holds across conditions, branch storage, and catalog fields. Live schema fetching with withTypes, add object, add automation, and x-workflow-input-schema resolution is the right long term bet because it stays correct when tenant objects change.

The tension is that the good core ships inside a package that undermines it. Hand written source is about 1,367 lines. Generated code is about 1,085,607 lines across 1,076 apps and 14,477 resources. Source generated output is 60 MB, dist is 67 MB, and every catalog regen rewrites 2,154 tracked files. Type checking stays fast today only because skipLibCheck is on. IntelliSense pays the price instead, since AppName is a 1,076 member union evaluated on each workflow.node() call. Two rewrites landed a day apart, 9e2a75c then b477463, and the second one alone touched 2,299 files with +120,011 and -187,322 lines. It deleted src/runtime, src/validation, src/project, filters, catalog, schema subdirs, evals, and about 30 test files, and replaced them with 9 test files. That was convergence toward the right small core. It also reset coverage to a thin shell over a huge typed surface.

The builder is the asset. The checked in catalog is the liability. Wrong workflows still typecheck, and the package teaches agents to deploy before it can validate.

Correctness gaps let wrong code through. Input<T> accepts extra keys because every generated Value carries [k: string]: unknown, so a typo like TYPO_FIELD typechecks in src/reference.ts. Output<T> accepts any property for the same reason, so p.output.nonexistent typechecks. An explicit <T> on code nodes erases input contracts because DynamicSchema maps to unknown in src/injected-type.ts, so wrong parameters pass only when you add the type argument meant to help. nativeCondition in src/filter.ts passes unknown operators like EQUALS through, stringifies Reference objects into invalid native shapes, and throws a raw TypeError for a bare {operator: 'AND'} with no action context. BREAK and CONTINUE fall through in src/graph.ts because only STOP and END terminate paths, so define([start, brk, after]) emits a bogus edge. There is no loop builder at all. Unresolved ua:dynamic markers leak into native JSON from src/dynamic-schema.ts and src/schema-loaders.ts. The /api/ guard in src/platform/client.ts checks the raw path but fetches a normalized URL, so /api/../admin passes the guard and requests /admin. Empty to empty conditions emit two edges to the join node. None of these fail the current 28 tests, which tells you the suite covers the happy path and misses the adversarial one.

Architecture will not scale in its present form. The build is rm dist, tsc -p tsconfig.build.json, cp src/generated dist/generated, in scripts/build.mjs. That copy puts 29 MB of .d.ts files that are never needed at runtime into every install. The exports map exposes only . and ./schema, so dist/platform and dist/cli build but stay unimportable. The runtime catalog loader uses createRequire with dynamic require in src/catalog.ts, which breaks static analysis in Vite, Next, and edge runtimes and defeats tree shaking. Regen takes an untracked external directory from process.argv, so two devs get different output from the same commit and sourceHash in the manifest verifies nothing per app. Namespaces like R0input are index derived, so inserting one action renames every later namespace and creates thousand line diffs. Overrides live partly in scripts/schema-overrides.ts for one app and partly inline in scripts/catalog.ts for another, with no registry and no tests, while 14 known converter failures ship as never or unknown and 36 duplicates get dropped silently. Build time tools including typescript, tsx, prettier, and json-schema-to-typescript sit in dependencies, so every library consumer installs a compiler and an execution primitive.

Developer experience blocks adoption in small ways that add up. There is no list, get, or describe. save without an id creates a duplicate automation silently. Token acquisition has no documented UI path and no whoami check, so first auth failure appears as a bare HTTP 401 deep in deploy. init does bare mkdir and validates flags after writing files, so a retry fails with EEXIST and a typo leaves a half created project. There is no validate, diff, dry-run, or test command, so the only server check is write then readback verify inside create and update. Global flags get swallowed per command, build dumps full JSON to stdout with no quiet flag, and a non ESM project gets a misleading missing default export error instead of an ESM diagnosis. Docs and code disagree on schedule trigger fields, on Condition versus NativeCondition versus FilterConditions which are one type with three names, and on what init actually creates. The README callable binding paragraph names no fields and gives no example. Skills copy with blind rm -rf plus cp, so local edits die on sync and package fixes never reach old projects except by resync.

Resilience and security need attention before wider use. The package root .cookie held a live looking session token at mode 644 during the audit, fanned out to three sandbox copies at 600. It is git ignored and excluded from the tarball, which is good, but any backup or screen share leaks it. The CLI executes arbitrary workflow TypeScript with full env and network access in src/cli/files.ts, with only a comment calling the file trusted. Catalog generation deletes src/generated before scanning and parses JSON with no try catch, so one bad input file can destroy the checked in catalog mid run. Network bodies buffer with no byte cap, platform strings parse with no size limit, pagination can run 1,000 pages with no operation deadline, and schema handling has no $ref policy, no depth cap, and no cycle detection in resolveSchema. A prototype path segment like __proto__ walks the chain in src/dynamic-schema.ts because that lookup lacks the hasOwn guard used elsewhere. All writes are non atomic. deploy activates triggers with no confirm. scripts have zero automated tests and tests never touch hostile inputs.

Direction is the last question. The honest name is typed builder, not executable workflow, because nothing executes except graph construction in src/define.ts. Keep node, define, condition, .output refs, and path availability. Keep live schema fetching and make it the default. Stop shipping src/generated in the tarball. Keep scripts/catalog.ts as internal tooling. Pivot the Pi scaffolding away from pinned models and forced deps. Keep platform commands but demote them below the pure builder. Kill the promised reverse emitter in src/native.ts and README.md until the forward path is stable. Overlap is real. The pi-mcp-workflow-authoring worktree owns packages/workflow-authoring with MCP tools and evals and fixes the same fidelity bugs this package deleted its validation layer for. Those two surfaces will diverge on every contract fix unless one owns authoring in writing. The automation-code-baseline-schema and automation-code-fetch-records worktrees are complementary upstream schema work, not rivals.

Action list

This is the ordered fix list. Each item names the files to touch.

  1. Strip index signatures at the Input and Output boundary in src/reference.ts. Add a Known key filter so generated [k: string]: unknown does not widen inputs or permit output.anything. Add positive and negative tsc fixtures and run them in bun test.
  2. Validate conditions at runtime in src/filter.ts. Reject unknown leaf operators, reject non AND or OR groups, reject Reference as filters or filter or define its semantics, and throw named errors with property and operator for missing filters. Add tests for EQUALS, bare AND, and empty filters.
  3. Preserve input contracts when <T> is supplied. Change src/injected-type.ts and scripts/injected-nodes.ts so T narrows only injected output positions while ResolveDynamic still checks x-workflow-input-schema inputs. Add the wrong parameters with <T> fixture.
  4. Strip ua:dynamic and never emit x-workflow-input-schema in src/dynamic-schema.ts unresolved paths, src/schema-loaders.ts, and scripts/catalog.ts. Extend dynamic-schema.test.ts to assert neither string appears in JSON.stringify(flow).
  5. Fix the client guard in src/platform/client.ts to check normalized url.pathname. Add a loopback server test that /api/../admin throws before fetch.
  6. Terminate BREAK and CONTINUE in src/graph.ts and decide LOOP semantics. Either add a loop builder or document linear only. Collapse the empty to empty join to one edge. Add tests for both.
  7. Stop tracking generated code. Gitignore src/generated/apps and data, track only manifest.json plus sourceHash, publish only data/*.json plus manifest, and ship types separately or per app. Verify with npm pack --dry-run under 2 MB.
  8. Split the dist payload. Stop copying .d.ts into dist, add exports entries for programmatic platform use or delete dist/platform from the build, and replace createRequire dynamic JSON in src/catalog.ts with a bundler safe import map plus a Set for manifest lookup.
  9. Make regen reproducible. Pin the source revision and generator version in the manifest, switch R{index} to slug based namespaces, add catalog --check in CI on sourceHash plus failure count, and elect a duplicate winner instead of dropping both copies.
  10. Build an override registry. Replace the one app function in scripts/schema-overrides.ts with an overrides table plus unit tests, move the inline utility_by_unifyapps patch out of scripts/catalog.ts, and add a pre convert normalization for the 14 known enum, comment, and $ref failures. Gate regen on zero new failures.
  11. Fix ID plumbing. Add workflow get <id>, make save write the returned id back or print an explicit created message, and add validate or dry-run so iteration does not require creating real automations.
  12. Harden init and flags. Validate provider, model, and thinking before writing, return a friendly exists error with --force and --name options, reject unknown or irrelevant flags per command, split build output to one line by default with a --print flag for JSON, and unwrap ESM double default in src/cli/files.ts with a clear message.
  13. Gate code execution. Require --run or a confirm before tsImport, refuse files outside the project root, and document that workflow files run unsandboxed with full env. Long term run them in a worker without credential passthrough.
  14. Make generation and sync atomic. Scan into a temp dir then rename, per file try catch with skip and record, npm install staging before removal in scripts/sync-sandbox.mjs, no clobber .cookie copy with 600 at creation, and tmp plus rename for all CLI writes.
  15. Bound untrusted input. Add a 5 to 10 MB response cap plus an operation deadline in PlatformClient, schema size and depth caps before compile, local # only $ref policy with expansion limits and pinned cwd, hasOwn guarded traversal in resolveSchema with rejection of __proto__, constructor, and prototype, and minimal node and edge content checks in workflowDefinition plus confirm on deploy.
  16. Fix dependency shape. Move typescript, tsx, prettier, json-schema-to-typescript, and @types packages to devDependencies, keep json-schema-to-ts as peer where consumers import it, and remove or justify the forced Pi agent dep in src/cli/init.ts.
  17. Collapse the type aliases. Keep FilterConditions as the single public name, deprecate Condition and NativeCondition exports, and use one vocabulary across README, skills, and help text.
  18. Promote README examples to tests. Add a happy path test mirroring the README verbatim plus a withTypes storage test, run tsc --noEmit as part of test, and document the update merge plus subset verify semantics at the save section.
  19. Version the agent bundle. Write a hash at setupPi and sync time, refuse to clobber locally modified skills without --force, and move sandbox internals plus SCHEMA-ADAPTERS.md out of the shipped README into contributing docs with a five step quickstart in their place.
  20. Decide ownership in writing within a week. Either this package owns authoring and packages/workflow-authoring becomes its eval backend, or MCP owns authoring and this package becomes the typed emit layer. Reintroduce a 10 case golden eval set in CI either way.

Dependencies are the workflow nodes source directory, the platform UAT host for live schema checks, and the Pi MCP worktree for the ownership call. Risks are stale generated types if regen lags platform changes, duplicate automations from lost IDs, and agent driven execution of untrusted workflow files. Open questions are per app lazy fetch design, loop authoring semantics, and whether the Pi runner stays pinned or becomes pluggable.

The package earns trust when wrong workflows fail fast locally, installs stay small, and one team owns correctness end to end.
