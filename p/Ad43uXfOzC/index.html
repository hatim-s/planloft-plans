2 · Corrections to your answers read this

Four things you picked have moved since. Each has a replacement that keeps your intent.

2.1 — D2: Clerk Elements is deprecated

You picked elements for fully custom auth markup. @clerk/elements was deprecated with Clerk Core 3 (March 2026) and only ever supported Core 2. The replacement covers the identical use case with less code: the redesigned useSignIn / useSignUp hooks, which expose step methods that map to the flow (signIn.password(), signIn.emailCode.sendCode()), a status property (needs_first_factor | needs_second_factor | complete), fetchStatus for loading, and structured errors.fields.

Plan takes: fully custom sign-in/sign-up markup built on Core 3 hooks. Same design control you asked for, actively maintained.

2.2 — E2: your three caching flags are now one

You checked ppr, use-cache, and dyn-io separately. In Next 16 they were unified: cacheComponents: true controls all three. experimental.ppr and the experimental_ppr route segment config have been removed — PPR is now the default App Router behavior under cacheComponents. So the config is one line, and it brings dynamic-IO strictness with it whether you want it separately or not.

Bonus behavior you didn't ask for but get: cacheComponents makes Next use React <Activity> to preserve component state across client-side navigation. Good for the canvas (map state survives a trip to the dashboard and back); needs checking against dropdowns/dialogs.

2.3 — E3: preloadQuery cannot live in the static shell

Convex's preloadQuery uses no-store, so any Server Component that awaits it is ineligible for static rendering. That is not a blocker — it is exactly what PPR's dynamic hole is for — but it dictates the shape: the page shell (nav, chrome, skeleton) is static, and preloadQuery lives inside a <Suspense> boundary that streams. Convex also gives no cross-call consistency between multiple preloadQuery calls, so each page makes exactly one.

2.4 — F7 + G1: AI Elements × Base UI is unverified

Base UI became shadcn's default in July 2026 (shadcn init defaults to it; -b radix opts out). AI Elements documents its prerequisites as shadcn/ui + Tailwind 4 + React 19, and says nothing about Base UI. Its components are shadcn-convention wrappers, so they most likely work — but "most likely" is not a foundation for a phase.

Plan takes: P0 spike installs AI Elements into a Base UI project and renders a streaming conversation. If it breaks, fallback is to hand-port the 7 components we actually need (Conversation, Message, Response, PromptInput, Tool, Task, Suggestion) — they are small, and we own the code either way.

2.5 — Clerk × cacheComponents has reported build failures

There are open reports of build/prerender errors when cacheComponents is enabled alongside Clerk. Known guidance: place <ClerkProvider> inside <body> rather than wrapping <html>, avoid a blanket <ClerkProvider dynamic> at the root, and push dynamic + Suspense down to the components that actually read auth. auth() in a server component opts that whole route into dynamic rendering.

Plan takes: P0 spike proves Next 16 + cacheComponents + Clerk + Convex preloadQuery builds clean before we commit to it. If it doesn't, cacheComponents ships on the public routes only (landing, share links) and authenticated routes stay plain dynamic — you lose nothing real, since authenticated map pages were never cacheable anyway.

Three rules that fall out of this:

  • Convex is the only writer. The AI route handler never mutates local state; it calls Convex mutations, and the canvas updates because it is subscribed. No dual-source-of-truth bugs.
  • Every mutation is an op batch. User edits and AI edits go through the same applyOps path, which records an inverse. Undo is uniform.
  • The canvas is client-only. xyflow never server-renders; everything around it streams.

4 · Convex data model

Proposed deviation from C1 — needs your yes/no. You picked normalized mindmaps / nodes / edges. For a mindmap the edge set is fully determined by the tree: every node has exactly one parent. A separate edges table would be a denormalized mirror we have to keep transactionally in sync for zero gain — and it makes "move subtree" a two-table write instead of one field update. I propose nodes carry parentLocalId and xyflow edges are derived on the client. If you ever want cross-branch links (non-tree edges), we add a links table then, and it means something different. Say the word if you want the edges table anyway.

// convex/schema.ts
export default defineSchema({
  users: defineTable({
    clerkId: v.string(),
    email: v.string(),
    name: v.optional(v.string()),
    imageUrl: v.optional(v.string()),
  }).index("by_clerk_id", ["clerkId"]),

  mindmaps: defineTable({
    ownerId: v.id("users"),
    publicId: v.string(),               // nanoid(10) — the URL id
    title: v.string(),
    visibility: v.union(v.literal("private"), v.literal("public")),
    lastOpenedAt: v.number(),
  })
    .index("by_owner", ["ownerId", "lastOpenedAt"])
    .index("by_public_id", ["publicId"]),

  nodes: defineTable({
    mindmapId: v.id("mindmaps"),
    localId: v.string(),                // xyflow node id, stable, e.g. "r-7"
    side: v.union(v.literal("root"), v.literal("left"), v.literal("right")),
    parentLocalId: v.optional(v.string()),   // undefined ⇒ root
    order: v.number(),                  // sibling ordering, sparse (100, 200, …)
    title: v.string(),
    description: v.optional(v.string()),
    link: v.optional(v.string()),
  })
    .index("by_mindmap", ["mindmapId"])
    .index("by_mindmap_local", ["mindmapId", "localId"])
    .index("by_parent", ["mindmapId", "parentLocalId", "order"]),

  operations: defineTable({             // undo log — one row per applied batch
    mindmapId: v.id("mindmaps"),
    actor: v.union(v.literal("user"), v.literal("ai")),
    messageId: v.optional(v.id("messages")),
    label: v.string(),                  // "Added 3 nodes under Imperialism"
    ops: v.array(v.any()),              // forward patch
    inverse: v.array(v.any()),          // exact undo patch
    undoneAt: v.optional(v.number()),
  }).index("by_mindmap", ["mindmapId"]),

  threads: defineTable({                // one chat thread per mindmap (F5)
    mindmapId: v.id("mindmaps"),
    ownerId: v.id("users"),
  }).index("by_mindmap", ["mindmapId"]),

  messages: defineTable({
    threadId: v.id("threads"),
    role: v.union(v.literal("user"), v.literal("assistant")),
    parts: v.any(),                     // AI SDK 7 UIMessage parts array
  }).index("by_thread", ["threadId"]),
});

Authorization (D4)

One helper, used by every query and mutation without exception. No function touches a table directly.

// convex/lib/auth.ts
export async function requireOwner(ctx, mindmapId) {
  const identity = await ctx.auth.getUserIdentity();
  if (!identity) throw new ConvexError("UNAUTHENTICATED");
  const user = await ctx.db.query("users")
    .withIndex("by_clerk_id", q => q.eq("clerkId", identity.subject)).unique();
  const map = await ctx.db.get(mindmapId);
  if (!user || !map || map.ownerId !== user._id) throw new ConvexError("FORBIDDEN");
  return { user, map };
}

Persistence semantics (C2, C3)

  • Canvas edits are batched and flushed on a 600 ms trailing debounce, with Convex optimistic updates so the UI never waits.
  • SaveMindmap.tsx becomes a status pill: saving… / saved 2s ago / offline.

5 · AI panel design

5.1 Tool contract

All tools are defined once with zod 4 schemas, executed server-side in the route handler, and each mutating tool returns the operationId that undoes it.

ToolInputKind
readMap{} → compact outline of the whole treeread
readSubtree{ localId, depth }read
addNodes{ parentLocalId, nodes: [{ title, description?, link? }] }write
updateNode{ localId, title?, description?, link? }write
deleteSubtree{ localId }write
moveSubtree{ localId, newParentLocalId, index? }write
expandBranch{ localId, depth, breadth } — generates then addswrite
restructureMap{ instruction } — whole-map rebalance, one op batchwrite

Q&A about the map (F2 summarize) needs no tool — it falls out of readMap plus a plain answer. Whole-map regeneration (F2 regenerate) is deleteSubtree(root children) + addNodes inside a single batch, so one undo reverses it.

5.2 Context strategy (F4)

You picked all three of selected-node, full-map, and read-tools. They compose rather than conflict:

  • The selected node is always injected as a context chip in the prompt — visible in the UI, removable.
  • The full map outline is injected when it is under ~200 nodes (measured in tokens, hard cap).
  • Above that cap, the outline is dropped and the model uses readMap / readSubtree instead. One code path, one threshold constant.

5.3 Undo model (F3 — auto-apply)

You chose auto-apply + undo over preview-diff. That is a better feel and a harder engineering bar: it makes the undo log load-bearing, not a nicety. The contract:

  1. Every mutating tool call writes its rows and its inverse patch in the same Convex transaction. There is no window where a change exists without its undo.
  2. All tool calls in one assistant turn share one operationId. One click undoes the whole turn, not one node of it.
  3. The affected nodes flash an accent highlight on the canvas for ~1.2s (B5 purposeful motion), so a change is never silent.
  4. Each assistant message renders an Undo action; undo is itself an op batch, so redo is free.
  5. deleteSubtree's inverse stores the full subtree payload. Deletes are recoverable, not tombstoned.

5.4 Panel UI (F1, F7, F8)

  • Right side, react-resizable-panels, collapsible, width persisted to localStorage. Sheet on mobile.
  • AI Elements: Conversation, Message, Response, PromptInput, Tool, Task, Suggestion, Reasoning, Actions.
  • Tool cards show the actual call and its result, so an auto-applied edit is always inspectable.
  • NodeAiEdit.tsx becomes "Ask AI about this node" — opens the panel, pre-fills the chip, focuses the input. The old popover mini-form is deleted.
  • /new stays as a first-run experience but calls the same tool layer via a one-shot server action.

8 · Delegation protocol

Per your G6 answer and CLAUDE.md. Each phase runs the same loop:

# 1. brief written to .logs/prompts/pN.md — API contracts, file list, patterns, constraints
timeout 5400 codex exec --sandbox workspace-write \
  -m gpt-5.6-sol -c 'model_reasoning_effort="high"' \
  "$(cat .logs/prompts/pN.md)" > .logs/pN.log 2>&1

# 2. liveness check — artifacts, not process existence
wc -l .logs/pN.log && git diff --stat     # unchanged for ~5 min ⇒ kill + restart

# 3. review: codex reviewer on logic  →  Opus subagent on quality/smells
# 4. pnpm tsc && pnpm lint && pnpm test
# 5. report to you → you approve → merge

Never piped through tail/grep (pipes buffer until exit and a healthy run looks hung). Always redirected to .logs/, always wrapped in timeout. Codex is stateless per invocation, so kill-and-restart is cheap — completed file writes survive.
