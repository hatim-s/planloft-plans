UACode on-prem security audit and hardening plan

TL;DR

Six parallel audits across RBAC, APIs, workflow execution, secrets, infrastructure, and sessions found 32 ship-blocking issues in the UnifyApps tree at main. Almost all share one root cause. Security controls default to off. This plan flips every control to fail closed, in code rather than config, in four phases before any on-prem ship.

The platform does not need more checks. It needs its existing checks turned on by default, so a missing properties entry cannot leave RCE or cross-tenant read open.

Situation

You asked for an airtight build for critical on-prem environments. Air gapped, flat network, hostile insider, no internet to save you. I ran six subagents against code as source of truth, not docs. Scope covered auth/, api/, api-platform/, workflow/, workflow-runtime/, infra/*, webhooks/, scheduler/, connectors/, docker/, k8s/, internal/, plus .github/ and build files.

Note on scope. There is no www/ directory in main. I treated www as the full web and API surface. That means the gateway on 30081, platform API on 30082, internal API on 30085, and all inbound webhooks.

The pattern repeats. Groovy sandbox off unless two tenants set it. SSRF strict mode off unless one tenant sets it. DPoP off. Internal auth off. Redis auth off. Webhook filter off for most paths. Each one is safe in isolation if operators set the flag. None of them are safe together on an on-prem install where operators miss one file.

What actually blocks the ship

Workflow code execution is the worst of it. Any user who can create a workflow can likely get RCE today. Groovy runs in process with no sandbox in default envs. JavaScript falls back to allowAllAccess(true). Python runs unsandboxed with a 10 minute timeout and author controlled pip installs. The third_party_library node lets an author name any class and runs setAccessible(true) on it. That alone justifies holding the release.

The second blocker is tenant escape. Tenant isolation is database selection driven by UserContext.customerId. Redis sessions live in a global namespace by default. The x-ua-assume-customer-id header can pivot tenants on unauthenticated filters. Session lookup ignores tenant. One header plus one stolen bearer crosses tenants.

The third blocker is unauthenticated reach. Internal API on NodePort 30085 is unauthenticated by default and includes decrypt oracles and customer creation. Inbound webhooks trigger workflows with no secret on most routes. A dt-ms controller permits all and ignores /internal/execute/code.

The rest matters but does not RCE on day one. Weak hashes, ECB, PKCS1 v1.5, CAST5, presigned URL TTLs, XXE, ReDoS, mass assignment, pagination bombs, missing throttles. Fix those in phase two and three, after the RCE and escape paths close.

Phase 0. Stop RCE and escape in one day

Do this first. Do not ship without it. Each item is a one to twenty line change with outsized effect.

Workflow sandbox must fail closed

Groovy nodes run in process with no SecureASTCustomizer when config is missing. See infra/scripts/src/main/java/com/unifyapps/scripts/groovy/SandboxGroovyProvider.java:95-99 and workflow/rt/src/main/java/com/unifyapps/workflow/rt/nodes/action/builder/CodeByUnifyAppsActionBuilder.java:121-128. Only uat-docebo and prod-es set groovy.sandbox.config in k8s/charts/global-properties/releases/. Every other env runs raw Groovy. An author can call Runtime.exec, read IMDS, read env secrets, or pin a thread with while(true) because CodeExecuteInlineAction.java:146-180 has no timeout and loads author JARs.

Impact is RCE on workflow-runtime as the service account, then lateral movement to Redis, Mongo, Kafka, and the K8s API.

Fix in code, not config. Bake a default deny SecureASTCustomizer into SandboxGroovyProvider so a null config returns a locked loader instead of a plain GroovyClassLoader. Flip workflow.action.code.inline.force.remote.for.non.standard to true so customer code runs in scripts-engine, never the workflow JVM. Wrap inline runs in ExecutorService.submit(...).get(nodeTimeout) with Future.cancel(true). Restrict jarLibs to admin uploaded allow listed JARs. Turn code.syntax.validation on by default.

Same story for JavaScript. See infra/scripts/src/main/java/com/unifyapps/scripts/javascript/SandboxJavaScriptProvider.java:54-75. The no config path calls allowAllAccess(true). The engine at scripts/engine-core/src/main/java/com/unifyapps/scripts/engine/javascript/JavascriptExecutionServiceImpl.java:44-61 sets no ResourceLimits and no timeout. Fix by inverting the default to HostAccess.NONE, IOAccess.NONE, allowCreateProcess(false), PolyglotAccess.NONE, no npm, plus statement and heap limits and a wall clock timeout. Loosening requires explicit config.

Python is off by default. See ai/python/python/code_snippet_executor.py:62 where python.code.execution.sandbox.enabled defaults to false, and BubbleWrapCodeExecutionAction.java:68-77 where language accepts bash. Prompt injected agents reach the same shell through SandboxCodeExecutorImpl.java:36-56. Fix by defaulting sandbox to true, denying egress except through an allow listed proxy, forbidding custom package_index_url for non standard workflows, stripping SA tokens and secrets from executor env, validating input keys as Python identifiers, and cutting the 600 second default at code_snippet_executor.py:54-59 down to 60 to 120 seconds.

The third_party_library node needs an allow list now. See workflow/rt/src/main/java/com/unifyapps/workflow/rt/nodes/action/code/ExecuteThirdPartyLibraryAction.java:33-43 and scripts/engine/src/main/java/com/unifyapps/scripts/engine/third_party/ThirdPartyLibraryExecutionService.java:56-80. It loads any class name, including java.lang.Runtime and javax.script.ScriptEngineManager, and calls setAccessible(true). Fix with a hard pair list of allowed class plus method, reject java.*, javax.script*, groovy.*, reflect*, net.*, require RAW_QUERY_ACTION or admin, and drop setAccessible(true).

Close the decrypt oracle and plaintext fallback

The internal decrypt endpoint has no @CriticalIntAPI annotation. See internal/src/main/java/com/unifyapps/internal/setup/CryptoConfigIntRestAPI.java:89-101 and internal/src/main/java/com/unifyapps/internal/filter/InternalAuthFilter.java:29 where internal.auth.enabled defaults to false. Any SSRF or flat network access gives a full KMS decrypt oracle for any customer ciphertext over GET with ?value= in logs.

Impact is total. All connector OAuth tokens, @Secure Mongo fields, S3 blobs, and PII vault contents decrypt.

Fix by adding @CriticalIntAPI to both CryptoConfigIntRestAPI and PropertiesIntRestAPI, flipping internal.auth.enabled to true, switching to POST with JSON body, and auditing every call. In the same change delete the plaintext fallback. See infra/crypto/src/main/java/com/unifyapps/infra/crypto/EncryptionProviderFactoryImpl.java:209-234 and AbstractCloudBasedEncryptionProvider.java:78-81 where a missing KMS config returns NoOpEncryptionProvider or the raw value when crypto.encryption.fallback.to.plaintext is true. Make the factory throw, fail the deploy, and add a metric that alerts if type="NO_OP" ever appears in prod.

Lock internal API, dt-ms, and cluster RBAC

Internal API on 30085 is unauthenticated by default, documented as such in docs/local-deployment-testing.md:417, reachable from scripts/run-everything.sh:14. That exposes create-customer, config sync, scheduler, and domain mapping. Fix with internal.auth.enabled: true plus internal.http.authentication.enabled: true in the on-prem profile, disable ingress for internal, and enable a default deny NetworkPolicy that only allows ingress-nginx.

Delete the open door in customers/dt/dt-ms/src/main/java/com/unifyapps/standalone/dt/SecurityConfig.java:24-33 where anyRequest().permitAll() plus ignored /internal/execute and /internal/execute/code gives code execution. Require admin auth and deny all except health.

Replace the Helm hook cluster-admin binding at k8s/charts/hybrid-mono/templates/helm-hook-rbac.yaml:14-26 with a namespaced Role limited to pods, configmaps, and jobs in the release namespace. Scope Sensu at k8s/charts/sensu/templates/clusterrole.yaml:6-10 the same way, drop pods/exec:create, and pull the hardcoded P@ssw0rd! at sensu-entrypoint.yaml:42 from an ExternalSecret.

Require webhook secrets

Most inbound webhooks run with no verification. See webhooks/src/main/java/com/unifyapps/webhooks/InboundAPI.java:91-101 where trigger-workflow/{customerId}/{workflowId} builds a UserContext from URL parts and calls startAsync, while WebhookAuthFilter.java:79 only covers connections/data/. GitHub, Slack, HubSpot, Meta, and Zoom handlers in webhooks/src/main/java/com/unifyapps/webhooks/apps/ skip HMAC entirely except Enigma. Enigma signs without the body at EnigmaWebhookAPI.java:153 and has no replay store.

Impact is unauthenticated workflow execution as system in the victim tenant, plus spoofed Slack block actions that trigger arbitrary workflows. Replay within 300 seconds duplicates side effects.

Fix by requiring a per workflow HMAC secret on every trigger-workflow route, verifying provider signatures before startAsync with constant time compare and a 300 second timestamp window, changing Enigma to sign timestamp + "." + rawBody, storing sha256(signature) in Redis with SETNX EX 600, setting webhook.auth.filter.drop-unknown-urls=true by default, extending the filter to all trigger paths, and returning uniform 404s with per tenant and per IP rate limits.

Fix session forgery and tenant pivot

Any caller with VIEW on one low code interface can mint a session for any user. See api/src/main/java/com/unifyapps/api/rest/SessionRestAPI.java:118-143 where request.getUserId() is never checked against caller or tenant. Fix by requiring an impersonate grant plus a same customer and same app check, or delete the endpoint and force the ImpersonationService grant path at tenant/.../governance/ImpersonationServiceImpl.java:80-95.

Drop ASSUME_CUSTOMER_ID from APIPlatformNoAuthFilter.java:90-95 entirely and only honor it for admin authenticators with allowedAdminScopes in APIPlatformServerAuthFilter.java:250-268. Turn on redis.acl.tenant.enabled, add a customerId predicate to every session Mongo query in RedisSessionStorageService.java:76-85, and reject session.customerId != domain.customerId in all auth filters.

Phase 1. Harden auth, SSRF, and storage in week one

Rotate refresh tokens and turn on DPoP

Refresh reuse is rolling and endless. See auth/client/src/main/java/com/unifyapps/auth/client/service/RedisSessionStorageService.java:183-205 where the same refreshTokenId is re saved with a fresh 30 day TTL, and AuthRestAPI.java:984-1002. DPoP is opt in and fail open at api/src/main/java/com/unifyapps/api/filter/AuthFilter.java:248-267 and DPoPProofVerifier.java:192-202, with replay, htm, and htu checks off and Redis errors returning true.

Fix by rotating to a new refresh ID on every use with a short grace window like OAuthServiceImpl.java:140-149 already does, capping absolute lifetime at 7 to 30 days, revoking families on reuse, password reset, and logout all. Enable dpop.proof.enabled, replay, htm, and htu, fail closed on store error, and replace the SSR exemption keyed on client supplied x-ua-trace-id: s_* with a server minted proof.

Enforce JWT audience and issuer

External JWT accepts claims=null. See auth/lib/src/main/java/com/unifyapps/auth/lib/oauth/service/JWTAuthServiceImpl.java:44-62 and infra/crypto/src/main/java/com/unifyapps/infra/crypto/jwt/JWTService.java:77-107. JWTIdentityProviderConfig.java:13-25 has no audience or issuer fields. kid drives a DB lookup on an unverified token at JWTAPIPlatformAuthenticator.java:46-55.

Impact is cross audience replay. A dev token or a token for another app sharing the same HMAC secret works in prod.

Fix by adding expectedAudience, expectedIssuer, and clock skew to configs, passing a non null claims map, verifying before any getKeyId or findBy use, rejecting alg=none, pinning expected alg, and replacing the unbounded publicKeyCache with a 5 to 10 minute Caffeine cache with explicit invalidation.

Make SSRF strict the default

The SSRF guard no ops on null props and allows 10/8 plus 172.16/12 unless strict mode is on. See infra/ssrf/src/main/java/com/unifyapps/infra/ssrf/SSRFUtils.java:279-282 and FileUtils.java:525-551 where the three arg readFile passes null. HttpExecutor.java:106-108 checks only baseUrl, never templated path, query, or headers. Only prod-es enables the flags. IMDS literal is blocked but attacker DNS plus redirect is not without rebinding protection.

Impact is K8s API, Vault, Redis, and Mongo reach from any workflow HTTP node, plus a file import path at UtilityRestAPI.java:306 and EntityRestAPI.java:200-203 that fetches EXTERNAL_URL server side.

Fix by requiring non null props, defaulting strict and DNS rebinding protection to true, resolving and validating IPs on every hop and pinning the address, blocking all private ranges, link local, and metadata IPs regardless of flag, validating path traversal, adding a per tenant egress allow list, and cutting the 1800 second timeouts in OkHttpClientImpl.java:82-87 to seconds.

Fix privilege boundaries in workflows and files

Workflows run as system. See ScheduledWorkflowTriggerHandlerImpl.java:159-163, EventBasedWorkflowTriggerHandler.java:344, and WebhookWorkflowTriggerHandler.java:240-244. The sensitive action gate at SensitiveActionAuthorizer.java:55-58 defaults to false and system always bypasses. Any author in a tenant can use any connection in that tenant because ConnectionServiceImpl.java:625-646 does no permission check. Fix by enforcing a USE permission at build, deploy, and execute time, enabling the sensitive check by default, removing the system bypass for customer authored workflows, and redacting decrypted credentials from logs and traces.

Files default to open. FileRestAPI.java:131-141 skips authz when accessScope is empty, and downloadFile at :160-216 decrypts any fileId with no ownership check. Fix with default deny, binding encrypted payloads to customer plus uploader plus expiry, and short lived signed URLs only.

Encrypt storage and scan uploads

S3 and GCS writes set no server side encryption. See S3CloudStorage.java:586-593 and GCPCloudStorage.java:84-96, with client side encryption off by default at EncryptionServiceStrategy.java:31-34. File validation is fail open at FileValidationServiceImpl.java:105-107 with antivirus, mime, and metadata scans skipped unless per customer config, and octet stream bypass. Fix with per customer KMS on every put and multipart, GCS kmsKeyName, bucket default SSE enforced by Terraform, secure defaults of antivirus on and deny by default mime, blocking octet stream mismatch, failing closed on scanner error, and quarantining on fail.

Stop logging secrets

Secrets land in logs and traces. See AbstractCloudBasedEncryptionProvider.java:78 logging the raw value, HMACService.java:33 logging secret plus data, and S3EndpointLogger.java:23 logging presigned URLs. Audit diffs persist decrypted Connection.userInput via GenericAuditLogGenerator.java:29-48. Fix with a central AuditRedactor on @Secure paths, logging only hash plus key id plus length plus prefix, and redacting auth and signature params in request log filters.

Phase 2. Fix injection, crypto agility, and network in weeks two to three

Input validation and NoSQL hardening

Only 46 @Valid uses cover more than 100 endpoints. Query, Page, Sort, Filter, Update, and AggregationQuery carry zero Bean Validation. Gateway api/ sets no max-body-size while api-platform allows 100M. Regex compiles user input verbatim in MongoFilterBuilder.java:203-205, OpenSearchQueryBuilder.java:147-150, and RegexFilterBuilder.java:55 while SafeRegex.java sits unused. MongoTemplateImpl.java:760-779 builds new Document(query) verbatim from a map, reachable from MongoIntRestAPI.java:95-96 with no collection allow list and limit=-1 for unlimited. Mass assignment binds Entity directly in EntityRestAPI.java:87-577 exposing ownerUserId, grants, projectId, version, and friends, and Update.java:12-14 honors client skipVersionIncrement and skipSchemaValidation.

Fix order is strict SSRF first, then RE2J plus length caps for regex, $ deny plus collection allow list plus @Max(1000) limits for internal Mongo, webhook tokens, denylists plus cleanContextualFields() for mass assignment, a global Page validator with @Max(200), and a @Valid sweep with @Size caps, recursive depth caps at 10, and StreamReadConstraints at 100 depth and 5M string length. Set api max body to 30M, return only errorId plus code when api.response.remove.error.details=true, and harden XmlMapper with SUPPORT_DTD=false and DISALLOW_DOCTYPE_DECL.

Crypto agility release

Hashing is PBKDF2WithHmacSHA1 at 65k iterations and 128 bit with a static legacy salt in HashingService.java:24-30, used by UserPasswordStoreImpl.java:92-93. AES ECB is first class in AESUtils.java:72-474 and AesECBEncryptionParams.java:12-14. RSA defaults to PKCS1 v1.5 in RSAUtils.java:43-184. PGP uses CAST5 in PGPUtils.java:309-310. HMACService.java:27-52 shares a non thread safe Mac, logs secrets, uses equals, and uses platform charset. Private keys hit world readable temp files in CryptoUtils.java:114-127.

Fix by moving to PBKDF2WithHmacSHA256 at 210k iterations and 256 bit with per user SecureRandom salts and rehash on login, deleting ECB support and defaulting to AES/GCM/NoPadding with 12 byte IVs, defaulting RSA to OAEPWithSHA-256AndMGF1Padding and rejecting PKCS1 for new configs, moving PGP to AES_256 with integrity packets, fixing HMAC to per call Mac, UTF8, and MessageDigest.isEqual, and writing keys with 0600 plus immediate delete and zeroed buffers. Include a re encrypt job for existing rows.

Network, pods, and air gap

gRPC uses plaintext by default at ChannelProviderImpl.java:70-73. Kafka is plaintext with TLS false at k8s/charts/kafka/values.yaml:8-14 and scripts/run-everything.sh:388. Redis has auth disabled at k8s/charts/redis-sentinel/values.yaml:11 with TLS no and a hardcoded 2028 session at run-everything.sh:170. Mongo local exec has no auth at run-everything.sh:88-267. Hostname verification is disabled globally in docker/Dockerfile.jvm:60. CORS reflects any origin with credentials at CORSUtil.java:59-60 and APIPlatformCorsFilter.java:82-83.

Pod hardening is opt in. unifyapps-base/values.yaml:42-81 leaves networkPolicy.enabled=false, empty security contexts, no read only root FS, and automountServiceAccountToken defaulting true. Init containers run as root with privileged sysctl and hostPath volumes at deployment.yaml:142-599. Secrets ship as plain env at :345-355 including HF_TOKEN. Most services set no limits and run one replica.

Fresh on-prem install halts offline. Public pulls from nodejs.org, github.com/BtbN, storage.googleapis.com, raw.githubusercontent.com, and repo1.maven.org plus private ECR plus curl installs in run-everything.sh:373-399 are hard requirements. Images are unsigned with latest plus IfNotPresent, no SBOM gate, and Trivy metadata suppressed in data-pipeline/flink-plugin/build.gradle:449-486. CI leaks INTERNAL_ADMIN_TOKEN and AWS keys into $GITHUB_ENV at execute-internal-request.yaml:71 and convert-volume.yaml:41-42.

Fix with an on-prem values profile. Default ssl=true for gRPC with Linkerd strict mTLS, SASL_SSL plus SCRAM-SHA-512 for Kafka with 3 replicas, Redis auth plus TLS plus a NetworkPolicy that only allows api, auth, and internal to 6379, Mongo enableAuth:true plus SCRAM plus TLS, delete the hostname verification disable line, enforce an explicit CORS allow list with trust.only.secured.origins=true, set runAsNonRoot 1001 plus drop ALL plus no privilege escalation plus RuntimeDefault seccomp plus read only root FS plus automountServiceAccountToken:false plus default deny NetworkPolicy, replace hostPath with PVCs, move secrets to secretKeyRef plus ExternalSecrets with a Vault or file provider for air gap, enforce requests==limits with 2 plus replicas for stateless, publish an air gap bundle with vendored images, Helm OCI, and pip plus maven mirrors plus digest pins plus cosign verify, and tighten CI to contents:read, persist-credentials:false, and short lived OIDC only.

Sessions, scheduler, and DoS

Login, OTP, and reset have no IP or global throttle. See PasswordLoginProvider.java:281-307, LoginFailureTrackerImpl.java:33-50 keyed only on user id, and ResetPasswordServiceImpl.java:74-77. Per user counters alone enable spraying across users and locking a victim with five bad tries. Pagination is uncapped in Page.java:11-80 so limit=2147483647 hits Mongo and Vespa directly. Scheduler builds Class.forName(jobClassName) from DB values at TriggerExecutor.java:158-165, accepts raw Query for bulk trigger ops with no forced customer id, and allows infinite immediate retries. GET logout still ships at AuthRestAPI.java:585-605 with block.get.logout.call=false. Session material rides in URLs at :281-478.

Fix with Redis fixed window limits per IP plus per account plus global burst, exponential backoff plus CAPTCHA, generic errors to stop enumeration, Page.MAX_LIMIT=100 with 200 for admin async plus cursor pagination beyond that, an allow listed job class registry with validated cron and zone plus forced customer scoping plus preventConcurrentExecution=true plus backoff and DLQ, POST only logout with origin checks, cookie only session transport with PKCE or DPoP proof for exchanges, and concurrent session caps with LRU evict.

Concrete steps near the end

Work in this order. Each phase gates the next.

Phase 0, day one. Fail closed Groovy, JS, Python, and C#. Allow list third_party_library. Add @CriticalIntAPI to KMS oracles and flip internal auth on. Delete plaintext fallback. Replace dt-ms permitAll. Fix hook and Sensu RBAC. Require webhook HMAC plus replay cache. Fix session forgery plus assume customer pivot plus Redis tenant mode.

Phase 1, week one. Rotate refresh tokens. Enable DPoP with replay, htm, and htu. Add JWT aud and iss. Enable SSRF strict plus DNS pinning. Enforce connection USE ACLs and enable the sensitive action gate. Default deny file downloads. Turn on S3 SSE plus ClamAV fail closed. Add audit redaction and stop logging secrets. Fix SSH verifier, HMAC thread safety, and key file perms.

Phase 2, weeks two to three. Sweep @Valid, RE2J, $ deny, mass assignment denylist, page caps, body limits, error redaction, XXE and zip bomb caps, presign TTL clamps, path traversal enforcement, and SAML HTML escaping. Ship the crypto agility release with new hashes plus GCM plus OAEP plus AES256 PGP and a re encrypt job. Land the on-prem network and pod profile with mTLS, SASL, auth, CORS allow list, seccomp, read only FS, resource limits, and ExternalSecrets.

Phase 3, before sign off. Throttle auth plus webhooks plus AI plus export. Fix scheduler allow lists and tenant scoping. Remove GET logout and URL bearers. Publish the air gap bundle with signed images, SBOM attestations, pullPolicy:Always plus digests, and a verified helm template | kube-linter | checkov | trivy | cosign verify gate. Rotate every secret touched by .gitleaksignore, the Sensu password, the admin platform token capped to 24 hours, and the year 2028 Redis session.

Verify with replay. Re run each exploit path from the audits. Workflow RCE as low priv author, tenant pivot header, session forgery, webhook trigger with no secret, decrypt oracle from an untrusted pod, regex and pagination DoS, mass assignment of owner and grants. Every path must fail closed with no flag set. Record the run in the release checklist.

Airtight does not mean bug free. It means a missing config line cannot open RCE or cross tenant read, and every remaining issue needs an authenticated, authorized, rate limited path with an audit trail.
