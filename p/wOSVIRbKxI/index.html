Automation Coder should not inherit the Workflow Planner and Workflow Builder skill lists wholesale. Those agents manipulate or describe workflow internals. Automation Coder writes TypeScript and delegates node ids, indexes, groups, edge wiring, and JSON serialization to the compiler. The right comparison is therefore about retained behavior, not copied files.

The current Hatim cut is close. It removed most structure-specific knowledge, consolidated runtime reliability, and retained performance guidance. Two changes remain: replace the old Storage-only skill with the existing unified UnifyApps data skill, then add callable contracts.

Move business and runtime knowledge. Leave JSON shape and graph construction with the compiler.

What moved

files-and-attachments, storage-records, and workflow-performance moved directly. They describe runtime contracts that remain true regardless of whether the author writes JSON or TypeScript.

code-by-unifyapps, code-node-selection, and utilities were consolidated into data-transforms-and-code. This is a good decision. The Coder needs one route from native operation to code node, plus sandbox, bindings, and result rules. It does not benefit from three overlapping entry points.

sql-query-builder became sql-nodes. The rewrite keeps connection, table, column, bind, and result-envelope discovery while dropping planner annotations and Builder payload examples.

workflow-error-handling and the runtime-diagnosis part of workflow-debugging were consolidated into workflow-reliability. This is the right abstraction for Coder: retry, timeout, fallback, protected execution, silent failures, and terminal run evidence without a separate planner repair-routing skill.

dates-and-time was split out of the utility material because date absence, milliseconds, unit selection, and silent "now" behavior are costly runtime traps. node-inputs-and-pills collects dynamic schemas, nullable values, mapped arrays, and output envelopes around the DSL and compiler.

The two remaining changes

1. Sync unifyapps-data to Hatim

Production Automation Coder has unifyapps-data V1, while Hatim still has storage-records V9. The unified skill covers app records, platform users and assets, Analytics, reporting SQL, exports, and the routing choice between them. It deliberately excludes object-definition and field-schema administration. Attach this skill to Hatim and remove storage-records after content readback proves the intended version.

2. Add callable contracts

The core prompt has the syntax. A skill should carry the deeper contract: who calls the automation, which trigger owns each input, which node owns the response, what every branch returns, whether the call waits, and which deployed version callers can reach.

Proposed final assignment

The target is nine Automation Coder skills on Hatim:

  • Keep: workflow-reliability, workflow-performance, dates-and-time, data-transforms-and-code, sql-nodes, files-and-attachments, node-inputs-and-pills
  • Replace: storage-records with unifyapps-data
  • Add: callable-contracts

Names may differ, but ownership should not overlap. Each new skill should use the current MCP services, point to live tenant schemas over memorized examples, and avoid workflow JSON, raw edge construction, group ids, node indexes, or legacy pill strings.

Implementation order

  1. Capture workflow-reliability and the current workflow-performance content in reviewed source if they are not already represented there.
  2. Attach unifyapps-data to Hatim and remove storage-records only after deployed readback.
  3. Add callable-contracts to Hatim.
  4. Evaluate the two changed domains on Hatim.
  5. Sync Hatim to production and verify deployed prompt and skill parity by id, version, and normalized content.

The result keeps Automation Coder small without making it naive: the compiler owns structure, while the agent owns operation choice, runtime contracts, and business behavior.
