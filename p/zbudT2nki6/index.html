This report measures all 25 prompts in Hatim's frozen UAC corpus against the published Automation Coder (Hatim) agent on agent-code-migration.uat.unifyapps.com. Each prompt ran in a clean agent session. Every saved automation then entered the platform TEST runner with the corpus fixture where one was supplied.

The result is mixed but useful. Twenty-two prompts built, and eleven of those passed TEST. The run spent $1.04 and processed 17.49 million tokens. Build and TEST remain separate verdicts because a saved automation is not evidence that the workflow runs.

Run 4 built 22 of 25 prompts. Eleven of the 22 saved workflows ran clean, so the full-corpus end-to-end rate is 11 of 25, or 44%.

What the failures say

The eleven runtime failures are not one defect. Two generated code nodes fail to parse, H05 in JavaScript and H10 in Groovy. HN07 emits an invalid formula. HN06 depends on an inactive connection, while HN13 passes an invalid page token to Google Calendar. The remaining failures hit missing or unsuitable fixture data: H01, H03, H04, H09, HN08, and HN10.

Three prompts never saved a workflow: H06, H11, and HN14. The other three apparent misses did save, but their final chat streams ended before returning an ID. Their successful upto=save trace outputs supplied the workflow IDs for TEST. No follow-up agent answer was used as evidence.

Several clean TESTs exercised empty, guard, or error-return paths. H02, H08, HN02, HN03, HN04, and HN09 returned empty collections or a no-alert state. HN01 completed without a response body, and HN05 returned status: error. Those runs prove the platform reached a clean terminal state for the supplied fixture, but they do not prove that every intended or side-effecting branch ran.

Evidence and reproduction

The frozen source is packages/uac/docs/eval/briefs-hatim.json. Run 4 evidence is in packages/uac/docs/eval/run-2026-09-11-hatim-run4/, including build responses, recovery responses, session usage, TEST outputs, fixtures, and the folded 25-row status file.

The next useful turn is controlled, not larger: fix one named failure class, keep the corpus and fixtures frozen, rerun all 25, and judge the change on both build rate and TEST rate.
