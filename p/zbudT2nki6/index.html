This report measures all 25 prompts in Hatim's frozen UAC corpus against the published Automation Coder (Hatim) agent on agent-code-migration.uat.unifyapps.com. Each prompt ran in a clean agent session. Every saved automation then entered the platform TEST runner with the corpus fixture where one was supplied.

The result is mixed but useful. Twenty-two prompts built. After rerunning the four cases originally classified as generated-script defects, fourteen of those workflows now pass TEST. The original run spent $1.04 and processed 17.49 million tokens. Build and TEST remain separate verdicts because a saved automation is not evidence that the workflow runs.

Run 4 built 22 of 25 prompts. After the post-merge script-case rerun, fourteen of the 22 saved workflows run clean. The effective full-corpus end-to-end rate is 14 of 25, or 56%.

What the failures say

The eight remaining runtime failures are not one defect. Six executed the brief's required error behavior. H01, H04, HN08, and HN10 rejected missing records; H03 rejected duplicate records; HN06 propagated the required child-automation failure. H05 still emits JavaScript the sandbox rejects. HN13 passes an invalid page token to Google Calendar. The post-merge rerun cleared the previous H09 month-arithmetic, H10 Groovy-parser, and HN07 formula-parser failures.

Three prompts never saved a workflow: H06, H11, and HN14. The other three apparent misses did save, but their final chat streams ended before returning an ID. Their successful upto=save trace outputs supplied the workflow IDs for TEST. No follow-up agent answer was used as evidence.

Several clean TESTs exercised empty, guard, or error-return paths. H02, H08, HN02, HN03, HN04, and HN09 returned empty collections or a no-alert state. HN01 completed without a response body, and HN05 returned status: error. Those runs prove the platform reached a clean terminal state for the supplied fixture, but they do not prove that every intended or side-effecting branch ran.

The rerun moves three cases from TEST failure to TEST pass. It does not change the 22/25 build denominator: these are replacement results for existing corpus cases, not four additional prompts. H05 remains the only unresolved generated-script failure from this group.

The preflight proved that the tenant accepted the session, the MCP service and tunnel served the merged tool list, the tenant connection pointed at that tunnel, and the agent answered. It also found that the published agent instructions were not byte-identical to the repository prompt: the published copy lacked the latest sandbox-tool row and one runtime-null guidance section. The numbers above therefore describe the configuration actually served by UAT, not a claim that every merged instruction change was published.

Original failed TEST triage

At the time of the original run, the 11 failures split into four generated automation defects, four cases without a usable positive fixture, two tenant dependency/data failures, and one connector catalogue defect. H09 crossed two layers: the first TEST used test despite the trigger's date-time schema; with a corrected timestamp, the workflow then failed because Instant did not support month arithmetic. The post-merge results for H05, H09, H10, and HN07 are recorded above.

Case Primary cause What should have caught or fixed it while building
H01 Fixture gap Discover a real region, design center, and lab description before positive-path TEST; otherwise retain LAB_NOT_FOUND as an expected negative-path result.
H03 Tenant data invariant Preflight the duplicate slug and report the fixture blocked. The brief explicitly requires duplicate stored matches to fail.
H04 Fixture gap Test with a real vehicle model ID; object schemas expose fields but not a usable record value.
H05 Generated JavaScript Escape the HTML attribute quotes and run JavaScript sandbox validation before save.
H09 Harness plus generated Groovy Honor JSON Schema date-time; replace Instant.minus(..., MONTHS) with calendar-aware month arithmetic.
H10 Generated Groovy Parse or compile the Groovy body before save. The DSL preserved the script; the script itself is invalid.
HN06 Tenant dependency Preflight the called automation and its active connections. Its existing OpenAI connection is inactive.
HN07 Generated formula Pass typed code-node parameters directly instead of constructing JSON with CONCATENATE; parse formulas before save.
HN08 Fixture gap, binding unproved Use a real applicant ID, then verify whether fetched records are flat or nested under properties. The negative fixture cannot decide this.
HN10 Fixture gap Use an employee ID that has shifts; the explicit empty-result failure is expected.
HN13 Catalogue/schema defect Add nextPageToken to the Calendar operation output schema and use it for paging. The catalogue exposes only nextSyncToken, which is not a page token.

The highest-leverage builder change is an executable pre-save gate: validate JavaScript, Groovy, and formulas with their real parsers. That would have stopped H05, H10, and HN07 before save. The next fix is a schema-aware fixture generator that respects format, enum, bounds, and corpus examples. Skill guidance is useful for avoiding HN07 and requiring preflights, but prompt text cannot repair missing connector metadata, inactive tenant dependencies, or absent fixture values.
