This report covers the 50-case T2W | E2E dataset using the TypeScript workflow SDK and Pi with GPT 5.6 Luna. It records the latest completed authoring attempts, reviewed TEST retries, and verified draft saves from the evaluation ending 13 September 2026 IST. No Sol tests were run in this round.

Thirty-six cases were attempted. Thirty-four compiled, and 33 were saved and read back successfully. Fifteen cases matched their reference outputs; a platform run reaching COMPLETED alone does not count as an expected-output pass.

Build, native execution, and expected-output correctness are separate results. The automation links below point to the generated drafts, not the reference workflows.

How to read the statuses

Build Completed means the authored TypeScript passed compilation and a draft was saved with matching GET readback. Build Failed means compilation or verified persistence did not complete. Case 09 compiled locally but failed at save, so its build is Failed.

TEST Successful means a native TEST completed and its observed output exactly matched the expected output. TEST Failed means the native run failed or its output did not match. TEST Not tested means no native execution occurred, or the expected-output check could not be performed. The Native TEST detail table makes the exceptional completed-but-unscored case 39 explicit.

Missing and empty dataset inputs were used as {}. External business actions were mocked; local variables, code and control flow executed normally. Nine drafts were saved solely for review after mock preflight blocked their TESTs. Names below come from the prompt or a concise description of it; some reference automation names are unrelated or generic.

What needs attention next

The largest coverage gap is the mock plan. Several generated workflows select an action or projection shape that differs from the reference automation. Those differences need case review and mocks based on the evaluated request. Missing mocks are not evidence that generated business logic failed.

Case 44 needs better Luna authoring convergence for the BFF branching flow. Case 45 needs live MQTT schema resolution. Case 09 needs a verified save after the HTTP 500; its unknown save outcome is retained, and no automation ID is invented. The mismatches in cases 04, 12, 19, 28 and 35 need prompt, output-contract or code review before retesting. Case 01 remains a failed native TEST with a query/schema versus mock-shape discrepancy.

The runner's local-list-mutation error was corrected, clearing cases 13 and 38. The SDK's contradictory Analytics aggregation dependency was corrected, allowing case 01 to compile. Runtime skill guidance now shows required-output guards and inclusion of referenced statements. All 72 PoC tests and TypeScript checks passed; the SDK passed 198 tests with four optional skips, its TypeScript check and build. The shared node_modules directory was reduced to 67 MB while retaining historical package tarballs and authored source.
