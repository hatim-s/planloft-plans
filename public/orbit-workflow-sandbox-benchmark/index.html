Workflow Agent benchmark

How long did someone wait for the workflows, and how much did all Workflow Agent LLM calls cost? The primary clock runs from the original Solution prompt to the last confirmed workflow deployment. Worker time is shown separately to account for parallel execution.

Longest measured legacy build

Invoice Reconciliation was the longest legacy case in the measured set. The original and its replay used the same prompt and both deployed all nine assigned workflows.

The legacy run used nine parallel workers. Their execution times add up to 2h 42m 16s. The longest worker took 34m 50s, and the actual first-start to last-end window was 34m 50s. The sandbox used one batch worker.

The sandbox deployed the workflows sooner. The last terminal trace arrived at about 42 minutes in both runs, and both parent traces recorded partial failure. The replay also left 15 extra undeployed stubs outside the nine approved workflows.

The replay’s $1.82 includes the batch worker and seven Workflow Agent status calls. The broader Solution total adds planning, app work and other agents, including Agent Builder work.

Case-by-case results

Worker time and concurrency

Longest worker is the longest single execution. Sum adds all worker execution durations, including overlap and observed retries. Elapsed worker window is the earliest worker start to the latest worker end, including gaps. When workers start together, the longest one is close to the visible worker window. Prompt-to-deployment also includes planning and provisioning.

Three sandbox worker rows use the first and last LLM span timestamps because their full execution boundaries were unavailable. Those are lower bounds. The Plant legacy trace did not establish individual worker boundaries.

Totals, means and medians

The sandbox saved 45/45 approved workflows and deployed 41/45. Four schedules remained held for activation approval. Snowflake binding and KPI errors mean a deployment does not prove business correctness.

The cost-paired group has six cases. Invoice Reconciliation accounts for its lower aggregate spend. The timing-paired group has seven cases because Plant has observed deployment time and missing legacy Workflow Agent cost. The matched prompts ran with different reasoning levels, connection bindings, cache conditions and workflow scopes. These are observed differences. A controlled replay is needed to isolate the effect of sandboxing.

Measurement notes

Legacy Workflow Agent cost sums exact displayed LLM-span prices where raw numeric pricing was unavailable. Sandbox cost sums deduplicated numeric LLM spans attributed to the Workflow Agent. Unattributable and missing prices stay unavailable. These prices exclude connector and infrastructure charges. The whole-Solution LLM cost in the longest case reconciles the original parent and app trace totals and all priced actor spans in the replay.

Time-to-deployment uses successful implementation receipts or a versioned nonstub deployment matched to the original episode. The Support historical row includes three workflow expansions and the Task Tracker historical row excludes a later fifth workflow. Different scope and unavailable histories remain explicit in the tables.
