6. Plan to push merge share from 35.2% toward 70–90%+

Factory already contributes 35.2% of merged PRs across www, nebula-plugin, ai-factory, and agent-platform. Growing that share across all 24 sub-orgs depends on two workflow-native levers paired with Gate 0 reliability fixes.

Lever 1 · All-team intake & debugging

AOA-style Slack mention bot relay

  • Bring Factory into every pod and on-call Slack channel using the AOA bridge pattern: explicit @AI Factory mentions and scoped watchers with channel, caller, and bot-loop allowlists.
  • Deterministic thread keys (slack:<workspace>:<channel>:<thread_ts>) + run ID reuse guarantee Slack retries never spawn duplicate sessions.
  • Start in read-only Diagnose with pinned QA run or trace links; escalate to Repair loops only after an owner approves diagnosis and write scope.
  • Local mapper passed 4 fixture tests and the 5-case retrospective Slack pilot yielded 3 new diagnoses (4 of 5 Factory coverage); next step is QA WATCH trigger wiring.

Lever 2 · Default PR quality gate

Same-head PR review & CI triage across the 4 repos

  • Standardize 2–3 distinct Factory review passes on the exact same GitHub head across www, nebula-plugin, ai-factory, and agent-platform once #36564 advisory guards and AF-1645 commit-checkout fixes are live.
  • Author pass (diff, scope, focused tests) → Intermediary developer pass (correctness, regression) → Tech lead pass (release risk).
  • Strict invariants: zero unapproved writes, new commits invalidate prior receipts, and CI triage compares red jobs against the pinned base with at most 1 bounded retry.
