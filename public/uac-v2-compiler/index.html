Why v1 kept breaking

Twelve agents, six GPT 6 Luna and six Claude Haiku 5.5, read the 173 commits that touched the v1 compiler and its MCP tools, two per slice. The postmortems are in docs/v2/postmortem/. Ranked by how many commits each cause explains:

The previous full eval saved 96.8% of briefs but only 53.1% ran clean. The failures were in what got saved, not in getting code to compile, so v2 is built to make a saved workflow correct, not just accepted.

The six rules

  1. One statement is one node. No lowering step adds a node the source does not show.
  2. Types reject programs, never choose output. Replace every generated type with any and the JSON is byte-identical. No lowering reads a type.
  3. One owner per encoding. pill.ts, formula.ts, filter.ts, operators.ts and value.ts are the only code that reads or writes those encodings.
  4. Nothing is ignored. Every AST node is consumed by one construct or refused with a located error and a fix. as, any, ! and @ts-ignore are errors.
  5. The compiler is pure. compile(source, ctx) with tenant facts loaded first. Nothing edits the JSON after lower, so the JSON that was checked is the JSON that is saved.
  6. Node ids are data. They live in the source as #id headers, so an edit is a copy by id, not a guess by position.

What an agent writes

This is Haiku's p19 from the final eval run, trimmed in the middle. It passed: it ran on the tenant and returned what the reference automation returned.

import { automation, blank, callable, js, op, s } from "@ua/automations";

export default automation(
  {
    name: "Employees Missing Bonus | GoogleSheets",
    trigger: callable({
      input: s.object({ spreadsheetId: s.string(), sheetName: s.string() }),
      output: s.object({ result: s.string() }),
    }),
  },
  (t) => {
    // Validate the inputs first
    if (blank(t.spreadsheetId) || blank(t.sheetName)) {
      return { result: "Missing spreadsheetId or sheetName" };
    }
    // Read the employee rows A1:E161
    const sheet = op("gsheets", "gsheets_get_spreadsheet_value", {
      spreadsheetId: t.spreadsheetId, sheetName: t.sheetName, range: "A1:E161",
      majorDimension: "ROWS", valueRenderOption: "UNFORMATTED_VALUE",
    }, { connection: "6ab4f54186782519cfd1ab26" });

    // Find rows with LeavesTaken above 0 and a blank BonusAmount
    const prep = js({ values: sheet.values }, s.object({ count: s.number(), message: s.string() }), ({ values }) => {
      /* … plain JavaScript, type-checked, emitted for the GraalJS sandbox … */
    });
    if (prep.result.count === 0) return { result: "No employees are missing a bonus" };

    op("slack", "slack_post_message_in_channel", {
      channel: "C0BE01QLY2G", messageType: "text", text: prep.result.message,
    }, { connection: "6af5f6ae57e6a453a5054d51" });
    return { result: `Posted ${prep.result.count} employees missing a bonus to Slack` };
  },
);

Every op() is typed from the shipped catalogue and the tenant's own schemas, so sheet.values, prep.result.count and the return are all checked. When something is wrong the agent gets a located error with a fix, for example:

  a template holding only one value keeps that value's type at run time.

Proof against the deployed corpus

The laws run over every deployed workflow in the corpus, 3,645 of them. A workflow the editor's own invariants rule out is refused by lift with a named reason. 30 are refused, and each one is pinned in the tests, so a new refusal or a refusal that starts lifting fails the suite.

The type checker on real code

The types law type-checks the printed source of every deployed workflow. 2,716 of 3,615 have no error. The other 2,629 errors are real disagreements between what deployed code does and what the catalogue or the workflow's own declarations say, such as a field the output does not declare or a return that breaks the declared contract. Each was reviewed and recorded in src/_tests_/types.residue.txt, in twelve commented groups. The suite fails if one appears or disappears. Compiling a workflow against its saved baseline demotes errors the baseline already had to warnings, so editing an existing workflow is never blocked by its history.

    Open items

    • Storage list fields from a bare list pill. v1 claimed the engine reads a bare pill into an array field as one element. That claim is false for js() parameters and callable returns, but nobody has run it for a storage record field. The check is one create-and-read-back run with two ids and two meeting rows, including empty and null attendee lists. If it fails, the compiler should lower those slots to a mapped array.
    • Retry counts above 5 on 32 deployed nodes. v2 keeps the saved values; the form allows at most 5.
    • Follow-ups that do not block: cacheConfig and rate-limit key syntax; moving the remaining llm-tools cleanup callers (get_node_schema, batch_upsert_nodes) onto lift and check; required keys for object-list add_item.
