1 · Today

What a reader sees on load

  1. All 1,077 edges draw at rest as straight grey lines. 726 of the 7,626 possible type pairs are connected, so every line crosses dozens of others and no path can be followed.

  2. Every node is 48px. Bug holds 22,562 records and UCB holds 4, and they look identical.

  3. At fit-to-view, names render at roughly 6px. A reader has to hover to learn what any node is.

  4. Hovering Account fades the rest and prints all 81 of its relationship labels at once, stacked on top of each other around the node.

  5. The legend filters Core, Secondary and Derived. All 124 types in this graph are Core, so the only grouping control does nothing.

2 · Diagnosis

Where the lines come from

Most big relationships in this schema are declared as every type in one set linked to every type in another. For all of the 25 largest relationships, every possible combination exists. The renderer draws that product, so a single modeling decision turns into a solid block of lines.

Collapse just the four families the data reveals on its own (types that share a relationship signature) and 1,077 edges become 389 typed links. One level up, at 8 domains, there are 23 links between domains.

4 · Everywhere

Rules that apply in every view

These also work as quick wins on today's canvas, before any new view ships.

  • Keep an edge budget.Never draw more than about 150 lines at rest. Past that, merge or hide until hover. Grafana's node graph stops at 200 nodes and shows "hidden nodes" markers instead of drawing everything.
  • Merge parallel edges.276 type pairs here carry more than one edge. Draw one line per pair with a count, and list the relationships on hover or in the inspector.
  • Collapse families automatically.Types with the same relationship signature merge into one node with a count. Stardog Explorer ships this: it groups nodes of the same class that share the same incoming and outgoing relationships, and a double-click splits the group.
  • Fade relationships nothing uses.Weight each schema edge by the number of record-level links behind it. A declared relationship with no records behind it should be a faint dashed line or hidden, so the canvas shows what the data actually does.
  • Park hubs in a context band.Account, Gdrive and Contact each receive a line from about 19 document types. Collibra puts such context nodes in a band above the main flow with thinner, lighter edges, so hubs stop pulling lines across the canvas.
  • Size by records, on a log scale.Bug (22,562) should outweigh UCB (4). Use a floor so small types stay clickable.
  • Label by priority and zoom.Show the names of the most connected and largest types first and reveal the rest as the reader zooms in, the way sigma.js budgets labels per grid cell. dbt's lineage graph shows only colored tags when zoomed far out.
  • Color edges by meaning.Ownership, provenance, work and conversation each get a hue. Grey is for whatever is out of focus.
  • Search first.Opening a type from search lands in focus lanes, not in the whole graph. Neo4j Bloom and Linkurious both open on a search box.
  • Grey out, don't remove.Filters dim what they exclude so the shape stays put, as in Linkurious and Bloom.
  • Keep positions stable.Expanding a domain or a family must not reshuffle the rest. yFiles calls this preserving the mental map.
  • Make the legend group by domain.Domains are how readers think about the graph. Core, Secondary and Derived are not, and here all 124 types share one value.
  • Pair the graph with a table.Every merged line and group opens a sortable list of the relationships or records inside it. OpenMetadata puts an impact table one tab away from lineage for when fan-out gets wide.

5 · Research

What other products do with dense graphs

Seven research agents (Claude Haiku 5.5, Gemini 4 Neon, GPT-6.1 Terra) read product docs, demos and posts. The pattern is consistent. No product that works at scale shows every node and edge at once. Each one starts from a scope, a group or a focus, and treats the whole graph as something the reader opens on purpose. The closest analogues, data catalogs and ontology tools, all split the type level from the record level, and one of them, Stardog Explorer, already ships the automatic family grouping proposed here.

6 · Order of work

Suggested order

  1. Quick wins on today's canvas.Merge parallel edges, collapse signature families, fade relationships with no records behind them, size by records, label by priority, color edges by relationship family, swap the legend to domains. No new view, and the hairball loses roughly two thirds of its lines.
  2. Focus lanes as the selection state.Replace the hover fan-out with the lanes layout. The inspector already loads a node's edges, so the data is there.
  3. Domain map and semantic zoom.Add a domain to node types (defaulting to the source system). Show domain tiles when zoomed out and types inside a domain when zoomed in, with stable positions between the two.
  4. Type groups in the schema.Let a relationship target a group: "any Document SUPERSEDES any Document" becomes one definition instead of 361. This fixes the density where it starts, and it also gives agents reading the graph fewer, clearer relationships to reason about.
  5. Same rules for the record graph.Add a supernode guard (Linkurious offers grouping and a cap when a node has more than a threshold of neighbours), draw join types as edges the way Palantir Vertex does, and move to a canvas or WebGL renderer such as sigma.js once a view holds thousands of records.
