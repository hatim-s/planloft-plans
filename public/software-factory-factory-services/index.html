Factory services design

This is the canonical project design for GitHub resolution, Planloft documents, portable project state and the standalone T3 MCP connection. It replaces the external factory-services-design.md as the maintained design. The external copy remains an archive of the original proposal, including superseded retry rules. Code and schemas remain authoritative for implemented behavior.

The implementation started at 5801563ef5f69a12236f03baf0b7d89ca33a067b. S1, S4 and S6 are still integrating in the shared checkout. This document states the intended safety contract and identifies current gaps. It is not an integrated verification receipt. The lead records final checks against the exact integrated revision.

Boundaries

Factory admits local work and records external intent before dispatch. T3 owns sessions and workspaces. GitHub owns remote issue and PR state. Planloft owns rendering and document hosting. Factory never merges code or deploys code or services. Project policy and an authorized operator command can authorize document publication through Planloft without a separate confirmation on every read or safe retry.

The four modules share the project runtime and durable store, rather than creating independent schedulers or transcripts.

Module Implementation ownership Responsibility
Project src/server/project, cli.ts, index.ts, http/project.ts Manifest discovery, runtime binding, records and commands
GitHub core/transport-github.ts, github, http/github.ts Hosting reads, completion dossiers, comment and close reconciliation
Documents docs and http/docs.ts under src/server Commit export, trusted rendering, publication intent and observation
T3 core/transport-t3.ts, t3, http/t3.ts Scoped MCP connection and explicit supported actions

src/shared/contracts.ts owns wire schemas and inferred types. Server modules own persistence and effects; web modules call HTTP. Shared code imports neither server nor UI. core/operations.ts advances durable operations with versioned compare-and-set. A local CAS prevents stale local transitions. It cannot fence a previously dispatched remote writer.

Portable project and machine state

.factory/factory.json contains version 1 project identity, repository slug and base branch, core policy, document manifest and portable publication policy. Unknown keys fail decoding. Document IDs and source names are unique. An MDX entry must explicitly set trust: "mdx". The schema now supports optional t3.connectionRef and string/boolean t3.preferences. This bootstrap omits it until a real machine connection is configured; endpoint and authentication remain machine-local.

This repository uses hatim-s/software-factory, base main, bundled theme editorial, manual Vercel publication and a 30-day TTL. The machine's existing Planloft config names Vercel project hatims-planloft, inspected read-only. That host binding is not committed. Init and this manifest use the verified bundled editorial theme. Core values are the current init/schema defaults, including bug and feature slots, OpenCode deepseek-v4-pro, two reviewers, three rounds, two repairs and a 30000 ms lease. These values do not establish provider availability or authorize model substitution. Astra orchestration and Sol implementation/review remain the agent workflow policy.

factory init generates a stable prj_ identity once and refuses an existing manifest unless reidentification is explicit. Every load checks the normalized origin against the manifest repository. Coordinators run from the main checkout; agent worktrees are for authored changes. A fork reidentifies rather than silently sharing another project's runtime.

Runtime lives at $FACTORY_DATA_DIR/projects/<projectId>/, defaulting beneath the user's local share directory. It contains the lock, core.sqlite, binding, artifacts and previews. Binding includes a portable runtime ID and machine-local paths. Moving to another existing checkout requires explicit rebind. Historical root databases are reported, never imported or opened as the new project database. Keep ignored .factory screenshots, reports and scripts intact.

Records are direct create-only writes into .factory/records. Factory never autocommits them. Portable record identity includes runtime identity and operation or ticket revision identity. Identical bytes at an existing identity succeed; different bytes surface a conflict and preserve the original. The current writer uses flat runtime-prefixed hash filenames and a factory.record/1 envelope, rather than the original proposal's nested resolution/publication folders. An operator commits records with ordinary Git. Credentials and machine paths must stay out of portable records.

A per-project local lock limits coordinators on one machine. Concurrent write-capable factories for the same project across machines are unsupported. A GitHub marker is evidence of a comment, not a lock or a distributed deduplication guarantee.

Durable external operations

core_operations stores versioned intent and separate observable phases. A partial unique index allows one open operation per subject. Executors persist sending intent before each external mutation and reconcile after interruption. Unknown outcomes keep ownership and block dependent work. Read failures keep uncertainty; a missing event or item never establishes absence by itself.

The operation worker shares CoreStore with ticket scheduling. Child-process publication keeps blocking host CLIs outside the coordinator event loop. Persisted records are retried create-only after terminal transitions. Local transaction success does not imply remote success or that a remote child stopped.

GitHub resolution

PR list/detail, check runs and Actions reads retain repository, head SHA, run and attempt identity. PR pagination uses bounded REST pages and can repeat entries during concurrent activity. Fetching a PR writes a local refs/factory/pull/<number> ref and reports whether it matches the observed GitHub head. It does not change a checkout or prove acceptance.

Resolution is an explicit submitted dossier, never an automatic consequence of a merge. v1 accepts only the bound repository for the issue and referenced PRs. A dossier reports summary, completion kind, close policy, optional pinned scope, acceptance and evidence. Reported validation stays distinct from observed checks. An unmet criterion cannot authorize a completed close. Secret-pattern checks are a tripwire, not a complete secret detector.

The deterministic dossier identity makes identical submissions return the same operation. A different dossier conflicts while that issue has open work. A draft endpoint submits nothing. Comment and close are separate effects so a posted comment with a rejected close remains visible.

Preflight reads the issue, full relevant closure/reopen timeline, PR states and checks. Requirements remain pinned throughout commenting, closing, unknown reconciliation and operator retry. Re-read title/body scope before mutations and after uncertain outcomes. A changed requirement blocks with scope drift. A Factory comment changing an issue timestamp is not itself a requirement change. Requirement changes in comments need human review. A human can still edit or reopen between the final read and the remote write; GitHub provides no conditional issue close fence to eliminate this race.

Comments carry a final-line operation/project/digest marker and the expected author. Marker matching adopts a visible comment and reports duplicates or edits. Missing comments after an uncertain send lead to attention, never an automatic repost. Retry is an explicit supported operator action with expected local version and fresh reconciliation, and can produce duplicate late arrivals. Preserve both receipts; delete nothing automatically.

Unknown close must reconcile current state, state reason, the full relevant sequence of closures and reopens, and the original intent. A closed issue with another reason or a human reopen is not successful completion of our intention. An open issue with no listed reopen is not permission to repeat PATCH. A lost reply, missing event, timestamp comparison or local process exit does not prove that the old write cannot still land. Retain unknown or attention until supported evidence permits recovery. Never fight a human reopen. Terminal stored resolution and fresh live observation are separate facts.

Issue body replacement remains observation-only. There is no merge endpoint, generic gh proxy or automatic resolution after merge.

Planloft documents

The manifest lists buildable product docs in .factory/docs. Architecture is MDX importing a local static TSX SVG. Planloft is pinned at 1.0.1; the older global CLI is not the Factory renderer. Mermaid fences are not the supported diagram path. Diagrams use currentColor, accessible SVG labels and a caption so the same source works in light and dark themes.

MDX is executable code. trust: "mdx" authorizes that execution and is not a sandbox. Render children receive a reduced environment without inherited credentials and a separate Planloft home. Source/import checks reduce accidental access; they do not make malicious MDX safe. Review imports and dependencies before trusting a revision.

Publication exports .factory/docs from git objects at an immutable commit. Default source is freshly fetched origin/<baseBranch>; an explicit immutable commit is allowed. Working-tree previews are dirty, local-only and unpublishable. Markdown identity covers its source blob; MDX identity conservatively covers all exported .factory/docs blobs. Identity also covers document metadata, slug, theme and renderer version. Actual imported dependencies must be included in the hash. External theme/package changes beyond the versioned identity remain an acceptance concern; no timestamp ordering or ancestry is inferred from creation times.

The runner calls Planloft's application API in a child Bun process. It renders noindex HTML, hashes the bytes, stores an immutable artifact and publishes that artifact as trusted HTML. A pre-send validation/configuration/authentication failure can be retried after correction under the configured authorization. Publication policy and the authorized operator command are sufficient; per-read or repeated confirmation is not required. Machine host and auth configuration stay outside Git.

A publish timeout, lost reply, host-stage failure or cleanup failure leaves an unknown writer. Do not resend or supersede it, or send a newer revision to that slug, until the old writer is safely settled or a supported explicit recovery establishes safety. Killing/reaping the local child is not remote cancellation. A matching fetched byte hash proves content presence at observation time only. It does not prove the writer settled or fence a late older write. The current implementation blocks uncertain publication retry with writer_unsettled; it has no general remote-settlement recovery protocol.

A returned receipt becomes published, then live only after bounded successful byte observation. Mismatch/unreachable eventually becomes unconfirmed. TTL expiry is separate from render success. Hosting is public and enumerable; noindex is not access control. Manual policy submits nothing until the operator publishes. The optional on-merge mechanism polls rather than receiving webhooks, and this repository does not enable it.

Standalone T3 MCP connection

docs/t3-connection.md owns current operating details and source evidence. Consult it before wiring the fourth module. T3 remains the session/transcript owner. Factory stores connection preferences, durable action intent and receipts, not a shadow transcript. Expose explicit typed actions, never a generic tools/call proxy.

Portable configuration should carry a connection reference and requested project/workspace/provider/model/options preferences. The host resolves the reference to the copied MCP URL, supported auth/OAuth state and expiry. Credentials, endpoints and machine IDs that encode location stay outside the committed manifest. Host approval/renewal owns OAuth acquisition. The official MCP SDK handles discovery, PKCE, loopback approval and private machine credential persistence. Reapproval is supported. Refresh is fixture-tested against a supporting receiver; the inspected T3 source advertises only authorization_code. The client distinguishes missing, rejected and forbidden auth; a 401 alone does not distinguish expiry from revocation.

Use a scoped transport. Initialize MCP, notify initialized, enumerate tools with bounded pagination and validate capabilities and advertised input/output schemas. Unsupported schema vocabulary fails before writes. Explicit reconnect discovers anew and never replays uncertain actions. Local close clears connection state, not remote work. Health must distinguish local connection status from active endpoint/auth/capability health.

Supported low-level actions currently include attach/read, observed configuration, question listing, root-thread launch with explicit project/provider/model/options, send and cancel. Delegate/task status/task cancel exist as explicit low-level methods. Launch verifies the returned requested configuration; mismatch may follow creation and retains ownership. Launch checks the requested provider, model and options against the advertised catalog before dispatch and verifies the returned configuration. Existing-workspace/new-worktree launch and permission approval transport are not implemented. A respond action has since been wired for question answers, but live acceptance remains unverified. Permission approvals stay in T3 UI. Never substitute models silently.

The T3Connection wrapper requires claims before launch/send/cancel/respond/task_cancel. The current host integrates CoreStore.claimT3 with connection and serialized payload identity. Shared action schemas, guarded route mounting and CLI status/config/execute are now wired. The host resolves FACTORY_T3_CONNECTIONS by symbolic reference. This is source-inspected integration, not evidence of crash recovery or authenticated live acceptance; the earlier S6 fixture used in-memory claims.

Reverify deduplication, authoritative absence and descendant termination against source and negotiated capabilities. Current evidence does not establish those guarantees across reconnect/session/restart. Gate only unattended operations that depend on them. Reads, explicit supported operator work and local authoring need not be globally disabled. Missing bounded messages, idle state, completed runs and cancellation acknowledgements cannot release unknown writer ownership or authorize replay. Scope disposal cancels local waits only.

Current gaps include automatic OAuth renewal, active health probing, long-lived incremental SSE completion, full typed question/configuration projections and authenticated live acceptance. Do not describe fixture success as live compatibility.

The lead runs bun run check, independent correctness review and real workflows in Hatim's personal Chrome profile at the exact integrated revision. Verify immutable record conflicts, historical DB preservation, unknown comment/close recovery, scope drift through every phase, uncertain old publication blocking new writers, credential-free rendering, deterministic MDX SVG output, MCP init/schema/auth failure, reconnect without replay and retained descendant ownership. Tests belong in _tests_ beside owners and use temporary repositories, SQLite, child processes and bounded fake receivers. Live GitHub mutation and document publication need the applicable operator authorization. This S5 change performs neither.

Product docs are discoverable through .factory/factory.json. Read architecture for ownership, operations for running/recovery, and API handoff for integration. Existing historical reports and licensing remain where they were. The external original proposal remains reference only and must not override this design's corrected safety rules.
